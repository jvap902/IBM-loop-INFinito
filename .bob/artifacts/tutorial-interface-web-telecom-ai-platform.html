Tutorial da Interface Web

Guia passo a passo para instalar, configurar e usar todas as telas da plataforma — do primeiro npm install até a leitura dos resultados.

1 — Pré-requisitos
FerramentaVersão mínimaComo verificar
Python3.10+python --version
Node.js18+node --version
npm9+npm --version
piplatestpip --version
Node.js 18+ é obrigatório apenas para a interface web. O backend Python funciona de forma independente.
2 — Configuração Inicial (uma vez)
1
Instalar dependências Python

Na raiz do repositório:

pip install -r requirements.txt
2
Criar o arquivo .env 
# PowerShell
Copy-Item .env.example .env

Abra o .env e defina no mínimo estas variáveis:

TOOL_API_KEY=telecom-dev-key-2024
GOLD_PARQUET_PATH=data/gold/features.parquet
TOOL_API_BASE_URL=http://localhost:8000
CORS_ORIGINS=http://localhost:5173
CORS_ORIGINS é obrigatório para a interface web funcionar. Sem ele, o browser vai rejeitar as chamadas ao backend.
3
Gerar o Feature Store sintético (se necessário)

Verifique se o arquivo data/gold/features.parquet existe. Se não existir:

python -c "
import numpy as np, pandas as pd, h3, pathlib
rng = np.random.default_rng(42)
n = 2000
hex_ids = list({h3.geo_to_h3(rng.uniform(-33,5), rng.uniform(-74,-34), 8) for _ in range(n*2)})[:n]
df = pd.DataFrame({'h3_id': hex_ids})
# ... (ver EXECUTION_GUIDE.md Seção 3.3 para o script completo)
"
4
Instalar dependências do frontend 
cd frontend
npm install
3 — Iniciando os Servidores

São necessários dois terminais simultâneos. Abra-os na raiz do repositório.

A
Terminal 1 — Backend (FastAPI)

Carregue as variáveis de ambiente e suba o servidor:

# Carrega o .env no PowerShell
Get-Content .env | ForEach-Object {
    if ($_ -match '^\s*([^#=][^=]*)=(.*)$') {
        [System.Environment]::SetEnvironmentVariable(
            $matches[1].Trim(), $matches[2].Trim(), 'Process'
        )
    }
}

# Sobe o servidor na porta 8000
uvicorn api.main:app --host 0.0.0.0 --port 8000 --reload

Verifique: http://localhost:8000/health deve retornar {"status":"ok"}.

B
Terminal 2 — Frontend (Vite) 
cd frontend
npm run dev

A interface estará disponível em: http://localhost:5173

O Vite faz proxy automático de todas as chamadas /v1/* para http://localhost:8000. Não é necessário configurar nada além do CORS_ORIGINS.

5 — Executando a Análise Completa (/run)

Esta é a tela principal. Ela dispara o agente LangGraph com os três eixos e exibe os resultados no Dashboard.

1
Informe a X-API-Key

Digite a mesma chave definida em TOOL_API_KEY no seu .env. Marque "Salvar na sessão" para não precisar digitar novamente.

Exemplo: telecom-dev-key-2024
2
Defina a Região

Três formatos aceitos:

ValorSignificado
allTodos os hexágonos do Feature Store
BR-SPLabel de região (qualquer string)
855198c7fffffffH3 parent cell ID (resolução 5 ou 6)
3
Selecione os Eixos

Marque os eixos desejados. Os três estão selecionados por padrão. É possível rodar apenas um ou dois.

Eixo 1 — Criticidade Eixo 2 — Expansão Eixo 3 — Segmentação
4
Escolha o Provedor LLM
OpçãoQuando usarCredenciais necessárias
StubSempre (padrão, funciona offline)Nenhuma
IBM watsonx.aiQuando houver conta IBMWATSONX_API_KEY no servidor
OpenAI GPT-4oQuando houver conta OpenAIOPENAI_API_KEY no servidor
5
Forçar re-execução (opcional)

Ative o toggle "Forçar re-execução" para ignorar verificações de freshness e garantir que todos os eixos rodem do zero.

6
Clique em "Executar Análise"

Uma sobreposição de loading bloqueia a interface enquanto o agente processa. O tempo varia entre 5 e 60 segundos dependendo do dataset e do provedor LLM. Ao concluir, você é redirecionado automaticamente para o Dashboard.

Se aparecer "504 Gateway Timeout", o agente demorou mais que o limite configurado. Aumente AGENT_RUN_TIMEOUT_SECONDS=180 no .env e reinicie o backend.
6 — Lendo o Dashboard (/)
①
Linha de KPIs (topo)

Cinco cartões com as métricas-chave do último run:

CartãoO que significa
Hexágonos AnalisadosTotal de células H3 processadas
Anomalias CríticasHexágonos flagados pelo Eixo 1; % do total
Clusters de ExpansãoGrupos identificados pelo Eixo 2 (HDBSCAN)
Segmentos de MercadoPerfis K-Means++ do Eixo 3
TAM TotalMercado endereçável total estimado em R$
②
Mapa Geoespacial (Leaflet)

Centroides dos hexágonos plotados sobre o mapa do Brasil. Use scroll para zoom e arraste para navegar. Clique em qualquer marcador para ver os detalhes:

● Vermelho — Eixo 1 Crítico ● Azul — Eixo 2 Cluster ● Verde — Eixo 3 Segmento
③
Gráfico de TAM por Cluster

Barras ordenadas por TAM estimado (R$). A barra mais alta (âmbar) representa a oportunidade prioritária. Passe o mouse sobre cada barra para ver o valor exato.

④
Gráfico de Segmentos (Donut)

Distribuição proporcional dos hexágonos por segmento de mercado. Cada fatia corresponde a um perfil K-Means++ (ex: Premium, Conectividade Essencial, Alta Vulnerabilidade).

⑤
Tabela de Hipóteses de Investimento

Lista priorizada de oportunidades gerada pelo agente. Clique no cabeçalho de qualquer coluna para ordenar. Principais colunas:

ColunaSignificado
PrioridadeP1 = crítico+expansão / P2 = alta / P3 = padrão
TAM (R$)Mercado endereçável estimado do cluster
Dom/HexMédia de domicílios por hexágono no cluster
Vel↓ MbpsVelocidade média de download atual
HHIÍndice de concentração de mercado (maior = menos concorrência)
JustificativaRationale gerado pelo agente (passe o mouse para ver completo)

A X-API-Key definida na tela de Análise Completa fica salva na sessão do browser. Nas páginas de eixo individuais ela é usada automaticamente — não precisa digitar novamente se já salvou.
8 — Log de Auditoria (/audit)
1
Aplique os filtros desejados

Todos os filtros são opcionais. Deixe em branco para ver os eventos mais recentes.

FiltroValores possíveis
Agent IDplanner, operational, system
Tipo de Eventotool_call, reasoning_step, report_generated, model_run
Run IDUUID de um run específico (cole do Dashboard)
De / AtéIntervalo de datas no formato YYYY-MM-DD
LimiteMáximo de eventos retornados (padrão: 100)
2
Clique em "Buscar"

A tabela é preenchida com os eventos. O tipo de evento aparece colorido para identificação rápida.

3
Expanda uma linha para ver o payload completo

Clique em qualquer linha da tabela para expandir e ver o JSON completo do evento. Clique no ícone ⎘ ao lado do Run ID para copiar o UUID para a área de transferência.

9 — Fluxo de Uso Recomendado
1 Acesse /run → configure região e eixos → clique "Executar Análise"
2 Ao redirecionar para / → leia os KPIs e identifique clusters prioritários no mapa
3 Acesse /axis1 ou /axis2 → ajuste thresholds → compare com o resultado do agente
4 Acesse /audit → filtre pelo Run ID do Dashboard → verifique a trilha de auditoria completa
10 — Solução de Problemas Comuns
SintomaCausa provávelSolução
Tela em branco ao abrir localhost:5173 npm run dev não está rodando Execute cd frontend && npm run dev no Terminal 2
Erro 401 ao executar análise X-API-Key não preenchida ou incorreta Verifique se a chave no formulário bate com TOOL_API_KEY no .env
Erro CORS no console do browser CORS_ORIGINS ausente ou errado no .env Adicione CORS_ORIGINS=http://localhost:5173 e reinicie o backend
504 Gateway Timeout Agente demorou mais que 120s Adicione AGENT_RUN_TIMEOUT_SECONDS=180 no .env
Mapa não carrega (tiles cinzas) Sem acesso à internet para o OpenStreetMap Verifique conexão; o mapa requer acesso externo para os tiles
data/gold/features.parquet não encontrado Feature Store não foi gerado Execute o script de geração sintética (Seção 2, Passo 3)
